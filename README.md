# pair-wise-yf-57 野外巡护离线调查应用

## 源提示词摘要
巡护员离线记录观察、轨迹点、样本编号、风险等级和现场情况，回到有网络环境后同步给站点负责人。多台设备会把同一次巡护拆成几包，设备时间可能回拨，负责人退回过一次的结论不能被晚到的旧包顶掉。负责人按能力范围、位置异常、证据缺失复核；样本交接从采集到送检逐段留不可改记录，退回时只作废受影响样本的后续交接，补齐后从退回点继续；设备换人升级后旧记录仍可查看和交接；包内单条失败不能影响其他条目，页面展示每条结果、失败原因和待补材料。

## 技术栈
Taro 3 + React + TypeScript + NutUI + Redux Toolkit + React Hook Form + Zod + Taro 国际化方案。

## 离线巡护包实现（src/offline）
- `types.ts`：离线包、事件、交接链、复核、逐条报告的领域模型。
- `device.ts`：设备端记录器。稳定巡护标识 `patrolId` 全程不变；设备内连续序号 `seq`
  只增不减、与设备时钟完全解耦；事件先入本地日志再按包序号封包，重传必须原样重发。
- `keys.ts`：事件幂等键（`设备+巡护+序号`）与业务键。
  观察按“分钟+地点”判同、轨迹按“设备+序号”判同、交接按环节判同。
- `crypto.ts`：FNV-1a 64 位哈希，交接链逐段串联。
- `engine.ts`：纯函数接收引擎。
  1. 包幂等：整包重传沿用第一次报告，不落任何新数据；
  2. 事件幂等：重传条目沿用第一次结果，晚到旧包改写内容/风险不会顶掉既有数据和负责人结论；
  3. 单条失败不影响同包其他条目；失败不固化，修正后可用相同 seq 重传成功；
  4. 顺序只信连续序号；时钟回拨、丢包、旧包晚到、序号缺口只产生告警；
  5. 样本交接链 `采集 → 交接 → 送检` 只追加，逐段带 `prevHash/hash`，篡改历史则链校验失败；
  6. 负责人退回样本只在受影响样本链上追加退回点，退回期间该样本晚到的后续交接逐条自动作废，
     其他样本不受影响；补齐追加 resume 记录，从退回点继续；
  7. 观察复核按能力范围 / 位置异常（与轨迹距离 1500m 阈值、无定位）/ 证据缺失三维度初判，
     结论按 revision 只追加；
  8. 升级前旧记录（只有采集人和时间）可导入建链，升级后正常查看、继续交接。
- `demoRig.ts`：两台设备的脚本化演示场景（拆包去重、回拨、单条失败、补发包晚到、退回、送检）。
- `engine.test.ts`：引擎自测，用 tsc 编译到临时目录后由 node 运行。

## 页面（pages/index）
- 设备端：离线写观察 / 轨迹 / 采集 / 交接，选设备、封包待发。
- 待接收队列：一键构造各场景包；每包可“联网接收”或“整包重传”。
- 接收报告：逐条展示 已入库 / 重传沿用 / 去重跳过 / 失败 / 自动作废、失败原因码、
  包级告警（回拨、丢包、旧包晚到）和待补材料；失败条目可“修正并补包重传”。
- 负责人复核：三维度标记与初判、退回 / 通过、复核历史只追加。
- 样本交接链：逐段不可改记录、退回 / 补齐、旧记录导入、链完整性校验与篡改演示。
- 全部状态通过 localStorage 持久化。

